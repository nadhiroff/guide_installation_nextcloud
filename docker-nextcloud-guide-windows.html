🛠️ Étapes 1–4 — Activation WSL2
01
Prérequis
Ouvrir PowerShell en Administrateur
▼

Toutes les commandes suivantes nécessitent des droits administrateur.

1
Appuie sur Windows + S et tape PowerShell
2
Clique droit sur Windows PowerShell → Exécuter en tant qu'administrateur
3
Clique Oui dans la fenêtre UAC qui apparaît
⚠️Sans droits admin, les commandes dism.exe retourneront une erreur d'accès refusé.
02
WSL2 — 1/3
Activer le sous-système Linux (WSL)
▼

Active la fonctionnalité Windows Subsystem for Linux — le composant de base qui permet à Linux de tourner dans Windows.

PowerShell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
1
Colle la commande dans PowerShell et appuie sur Entrée
2
Attends le message "L'opération a réussi" (ou "The operation completed successfully")
💡/norestart évite le redémarrage immédiat pour pouvoir enchaîner les commandes.
03
WSL2 — 2/3
Activer la plateforme de machine virtuelle
▼

WSL2 fonctionne avec un vrai noyau Linux dans une VM légère. Cette commande active le composant de virtualisation nécessaire.

PowerShell
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
1
Exécute la commande dans le même PowerShell admin
2
Attends à nouveau le message de confirmation de succès
⚠️Processeur AMD → vérifie que SVM Mode est activé dans le BIOS. Processeur Intel → c'est Intel VT-x.
04
WSL2 — 3/3
Redémarrer & définir WSL2 par défaut
▼

Les deux fonctionnalités précédentes nécessitent un redémarrage complet. Ensuite on configure WSL pour utiliser la version 2 par défaut.

1
Redémarre ton PC : Windows + X → Arrêter/Redémarrer → Redémarrer
2
Après le redémarrage, rouvre PowerShell en admin (même procédure qu'étape 1)
3
Exécute cette commande pour définir WSL2 comme version par défaut :
PowerShell
wsl --set-default-version 2
✅Un message sur les différences WSL1/WSL2 apparaît — c'est normal et confirme que WSL2 est bien activé.
🐳 Étapes 5–6 — Docker & Nextcloud
05
Docker Desktop
Installer & configurer Docker Desktop
▼

Docker Desktop est l'interface graphique qui gère Docker sur Windows. Il utilise WSL2 comme backend pour des performances optimales.

1
Va sur docker.com/products/docker-desktop et télécharge l'installeur Windows
2
Lance Docker Desktop Installer.exe — coche Use WSL 2 instead of Hyper-V si demandé
3
Accepte les conditions et termine l'installation — Docker peut redémarrer Windows
4
Au premier lancement, accepte les Terms of Service
5
Attends que l'icône Docker dans la barre des tâches devienne verte — Docker est prêt !
6
Vérifie l'installation dans PowerShell :
PowerShell — Vérification
docker --version docker compose version
💡Si Docker n'est pas reconnu, ferme et réouvre PowerShell. Docker ajoute ses binaires au PATH au démarrage.
06
Nextcloud
Créer le docker-compose.yml & lancer Nextcloud
▼

On utilise Docker Compose pour démarrer Nextcloud et sa base de données MariaDB en une seule commande.

1
Crée le dossier D:\Nextcloud
2
Dans ce dossier, crée un fichier nommé exactement docker-compose.yml avec ce contenu :
docker-compose.yml
services: nextcloud: image: nextcloud container_name: nextcloud ports: - "8080:80" volumes: - nextcloud_data:/var/www/html environment: - MYSQL_HOST=db - MYSQL_DATABASE=nextcloud - MYSQL_USER=nextcloud - MYSQL_PASSWORD=monMotDePasse123 depends_on: - db restart: unless-stopped db: image: mariadb container_name: nextcloud_db environment: - MYSQL_ROOT_PASSWORD=rootPass456 - MYSQL_DATABASE=nextcloud - MYSQL_USER=nextcloud - MYSQL_PASSWORD=monMotDePasse123 volumes: - db_data:/var/lib/mysql restart: unless-stopped volumes: nextcloud_data: db_data:
3
Dans PowerShell, navigue vers le dossier et lance les conteneurs :
PowerShell — Lancer
cd D:\Nextcloud docker compose up -d
4
Attends ~2–5 min que Docker télécharge les images (première fois uniquement)
5
Ouvre http://localhost:8080 dans ton navigateur et crée ton compte admin
⚠️Remplace monMotDePasse123 et rootPass456 par tes propres mots de passe sécurisés avant de lancer.
⚙️ Étape 7 — Gestion des conteneurs
07
Gestion Docker
Redémarrer & vérifier les conteneurs
▼

Si tu vois l'erreur "container is not running" ou que Nextcloud ne répond plus, voici comment redémarrer et diagnostiquer.

1
Va d'abord dans le dossier Nextcloud :
PowerShell
cd D:\Nextcloud
2
Redémarre tous les conteneurs :
PowerShell — Redémarrer
docker compose up -d # Lance les conteneurs en arrière-plan # Si déjà actifs, recrée seulement ceux qui ont changé
3
Vérifie que les deux conteneurs tournent bien :
PowerShell — Vérifier l'état
docker ps # Résultat attendu : # NAMES STATUS # nextcloud Up 2 minutes # nextcloud_db Up 2 minutes # Si un conteneur est absent → regarder les logs ci-dessous
4
Si un conteneur s'arrête, consulte les logs d'erreur :
PowerShell — Logs d'erreur
docker compose logs nextcloud docker compose logs db # Affiche les erreurs de démarrage docker compose logs -f # Mode live : suit les logs en temps réel (Ctrl+C pour quitter)
5
Toutes les commandes de gestion utiles :
PowerShell — Référence complète
# Démarrer les conteneurs docker compose up -d # Arrêter les conteneurs (données conservées) docker compose down # Redémarrer sans recréer docker compose restart # Voir les conteneurs actifs docker ps # Voir TOUS les conteneurs (même arrêtés) docker ps -a # Mettre à jour Nextcloud et MariaDB docker compose pull && docker compose up -d
✅Après docker compose up -d, attends ~10 secondes puis recharge http://localhost:8080.
🌐 Étapes 8–10 — Accès par IP & Trusted Domains
08
Trusted Domains — Problème
Erreur "Accès depuis un domaine non approuvé"
▼

Quand tu accèdes via ton adresse IP locale (ex: 192.168.88.194) au lieu de localhost, Nextcloud bloque la connexion. Ce problème arrive aussi à chaque changement de réseau WiFi.

⚠️ Message : "Accès à partir d'un domaine non approuvé — veuillez contacter votre administrateur. Modifiez la variable trusted_domains dans config/config.php"
1
Trouve ton IP locale actuelle :
PowerShell — Trouver son IP
ipconfig # Cherche "Adresse IPv4" sous WiFi ou Ethernet # Exemple : 192.168.88.194
2
Assure-toi que le conteneur tourne avant de continuer :
PowerShell
docker ps # Si nextcloud n'apparaît pas : cd D:\Nextcloud && docker compose up -d
💡L'étape 9 ajoute des wildcards qui couvrent automatiquement tous les futurs réseaux — tu n'auras plus jamais ce problème.
09
Trusted Domains — Solution
Ajouter tous les domaines approuvés (une seule fois)
▼

On ajoute 5 trusted_domains : localhost, ton IP actuelle, et des wildcards pour tous les réseaux courants. À faire une seule fois — ça fonctionnera sur tous tes futurs réseaux.

PowerShell — 5 commandes une par une
# 0 — localhost (accès direct sur ta machine) docker exec -u www-data nextcloud php occ config:system:set trusted_domains 0 --value="localhost" # 1 — Ton IP actuelle (remplace par la tienne via ipconfig) docker exec -u www-data nextcloud php occ config:system:set trusted_domains 1 --value="192.168.88.194" # 2 — Tous les réseaux 192.168.x.x (WiFi maison, bureau, école...) docker exec -u www-data nextcloud php occ config:system:set trusted_domains 2 --value="192.168.*.*" # 3 — Réseaux 10.x.x.x (hotspot mobile, VPN, certaines entreprises) docker exec -u www-data nextcloud php occ config:system:set trusted_domains 3 --value="10.*.*.*" # 4 — Réseaux 172.16.x.x (Docker interne, réseau d'entreprise) docker exec -u www-data nextcloud php occ config:system:set trusted_domains 4 --value="172.16.*.*"
1
Lance les 5 commandes une par une — chacune doit répondre "System config value trusted_domains => X set to..."
2
Vérifie que tout est bien enregistré :
PowerShell — Vérification
docker exec -u www-data nextcloud php occ config:system:get trusted_domains # Doit afficher les 5 entrées : # - localhost # - 192.168.88.194 # - 192.168.*.* # - 10.*.*.* # - 172.16.*.*
✅Recharge Nextcloud dans le navigateur — l'erreur ne reviendra plus jamais sur les réseaux 192.168.x.x, 10.x.x.x et 172.16.x.x.
⚠️nano introuvable dans le conteneur ? Installe-le avec : apt-get update && apt-get install -y nano — ou utilise vi déjà présent (i pour éditer, Échap puis :wq pour sauvegarder).
10
Trusted Domains — Bonus
Script : mettre à jour l'IP automatiquement
▼

Si tu changes souvent de réseau et qu'une nouvelle IP sort des plages wildcard, ce script PowerShell détecte et met à jour ton IP en une seule commande.

1
Crée un fichier update-ip.ps1 dans D:\Nextcloud avec ce contenu :
update-ip.ps1
# Détecte l'IP locale actuelle automatiquement $ip = (Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -notlike "127.*" -and $_.IPAddress -notlike "169.*" } | Select-Object -First 1).IPAddress Write-Host "IP detectee : $ip" # Met à jour trusted_domains dans Nextcloud docker exec -u www-data nextcloud php occ config:system:set trusted_domains 1 --value="$ip" Write-Host "Nextcloud mis a jour !" Write-Host "Acceder via : http://${ip}:8080"
2
Lance le script quand tu changes de réseau :
PowerShell — Lancer le script
cd D:\Nextcloud .\update-ip.ps1
💡Avec les wildcards de l'étape 9, tu n'auras presque jamais besoin de ce script. Utile uniquement si ton réseau utilise une plage d'IP non standard.
